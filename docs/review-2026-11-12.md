## Auth review notes (no defect)
- Parallel first requests: layout.tsx serialises via shared `ready` promise (handshake once); on handshake failure `ready` resets and the request goes tokenless -> server mints a new id (returned in x-session-id, stored).
- Legacy claim: first request wins; later raw-id requests get a new minted session. Residual risk: anyone knowing a legacy raw id can claim it first (inherent).
- Expired (>180d) / forged tokens -> verify null -> raw id rejected -> new session; verified in prod flow.
- Every header-less API call (curl, scripts, non-browser clients) mints a new session and a `guest_created` log line + session entry only when state is touched; no rate-limit on minting is visible here (memory growth risk).
- Mutations: 409 on stale x-state-version only if header sent (opt-in). RNG state lives in session object, persisted with cache; no cross-session sharing (non-request code falls back to 'default' session / Math.random).
